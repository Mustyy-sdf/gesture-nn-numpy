## Неделя 1

### 13.10 — один нейрон (`neuron.py`, `neuron_np.py`)

- Нейрон делает три вещи: умножает каждый вход на его вес, складывает и прибавляет смещение (bias).
  Пример: входы `[1, 2, 3]`, веса `[0.2, 0.8, -0.5]`, смещение `2` → `0.2 + 1.6 − 1.5 + 2 = 2.3`.
- Вес показывает, насколько важен вход. Отрицательный вес — нейрон «голосует против» этого входа.
- Весов столько же, сколько входов (для руки — 42). Смещение одно на нейрон: если дать каждому входу своё смещение, они всё равно сложатся в одно число.
- Смещение — это порог: оно решает, сколько «набрать», чтобы нейрон сработал. Веса решают, на что нейрон смотрит, смещение — насколько легко он срабатывает. Без смещения при нулевых входах нейрон всегда выдаёт 0.
- Ловушка: `zip` молча обрезает лишнее, если списки разной длины. При 3 входах и 2 весах программа выдала неправильный ответ без всякой ошибки.
- В NumPy то же самое делает `np.dot(inputs, weights)`, и при разной длине он сразу выдаёт ошибку `shapes not aligned`.
- Хвост `2.3000000000000003`: компьютер хранит числа в двоичном виде, а 0.1 в двоичном — бесконечная дробь (как 1/3 = 0.333… в десятичном). Поэтому `0.1 + 0.2 = 0.30000000000000004`. Дробные числа сравнивают через `np.allclose`, а не через `==`.

### 14.10 — слой из нескольких нейронов (`layer.py`)

- Все нейроны слоя получают **одни и те же** входы, а веса и смещение у каждого свои. 3 нейрона на 4 входа: 12 весов и 3 смещения.
- Веса удобно хранить в матрице, смещения — в векторе.
- `.shape` — сначала строки, потом столбцы: `.shape` равен `(N, M)`, где N — строк, M — столбцов. `shape` — свойство, а не функция, скобки после него не ставят.
- `(3,)` — одномерный массив из 3 чисел. У него нет ни строк, ни столбцов. Строка — это уже `(1, 3)`, столбец — `(3, 1)`, их пишут с двойными скобками.
- Правило умножения матриц: число столбцов первого множителя **равно** числу строк второго. `(3, 4) · (4,)` работает, `(4,) · (3, 4)` — нет.
- Если одномерный массив стоит в `np.dot` первым, он считается строкой `(1, 4)`. Если вторым — столбцом `(4, 1)`. В ответе эта временная единица убирается.
- `.T` — **транспонирование**: строки становятся столбцами, `(3, 4)` → `(4, 3)`. Не путать с обратной матрицей, это совсем другое.
- Много примеров сразу (batch): входы — матрица, строка — один пример (кадр), столбец — один признак (координата).
  Ответ слоя: строка — пример, столбец — нейрон. Это договорённость, NumPy сам этого не знает.
- Смещения `(3,)` прибавляются к каждой строке ответа `(3, 3)` — это broadcasting: NumPy «растягивает» меньший массив.
- Что сделал не так и исправил: функция использовала списки, созданные снаружи. При втором вызове в них оставались старые числа, и всё падало. Списки должны создаваться внутри функции, а данные — приходить через параметры.

### 15–17.10 — функция активации ReLU (`relu_plot.py`)

- Без функции активации слои **схлопываются**: два линейных слоя `y = 2x + 1` и `z = 3y − 4` дают `z = 6x − 1`, то есть опять один слой. Сколько слоёв ни ставь, сеть проводит только прямые границы.
- Сеть при этом учится, но может немногое. Функция активации добавляет излом (нелинейность), и сеть может строить кривые границы между жестами.
- ReLU: если число больше нуля, оставить его, иначе 0. Rectified Linear Unit, «выпрямитель», как диод.
- Проверка нелинейности: `ReLU(3 + (−3)) = 0`, а `ReLU(3) + ReLU(−3) = 3`.
- Нейрон с ReLU: `ReLU(w·x + b)`. Излом («шарнир») — там, где `w·x + b = 0`, то есть `x = −b / w`. Смещение двигает шарнир, вес задаёт крутизну и направление.
- Три нейрона с ReLU могут нарисовать «горбик», а без ReLU те же нейроны схлопнулись в 0 (график в `relu_plot.py`: вспомогательный код написал Claude, функцию ReLU в нём — я).
- Мёртвый нейрон: если он молчит на всех данных, обучение его уже не оживит. Главный недостаток ReLU.
- ReLU применяется к каждому числу отдельно, размер массива не меняется.
- `np.max` **сворачивает** массив: из многих чисел — одно (или по одному на строку или столбец через `axis`).
  `np.maximum` сравнивает **попарно** два массива или массив с числом, размер не меняется. Для ReLU нужен `np.maximum(x, 0)`.
- Ловушки: `np.max(x, 0)` молча возвращает одно число (второй аргумент — это `axis`), обычный `max(0, x)` падает с ошибкой.
- `import файл` выполняет весь файл. В файлах для импорта должны быть только функции и классы.

### 18.10 — свой фреймворк: классы (`nn/`)

- Класс — это чертёж, объект — вещь, сделанная по нему. Класс хранит вместе данные (веса) и действия (`forward`), у каждого объекта свои данные. Метод вызывается через объект: `dense1.forward(...)`, внутри класса — через `self`.
- `Layer_Dense`: веса размером `(n_inputs, n_neurons)` — тогда `np.dot(inputs, weights)` работает без `.T`. Смещения — нули размером `(1, n_neurons)` (договорённость из книги: всё двумерное). В `forward` сохраняю входы — они понадобятся в `backward`.
- `np.zeros((1, 3))` — размер передаётся одним кортежем, двойные скобки. `np.zeros(1, 3)` — ошибка.
- **Почему веса случайные, а не нули.** Если веса одинаковые, все нейроны слоя выдают одно и то же, получают одинаковые изменения при обучении и навсегда остаются копиями — 64 нейрона работают как один. Случайные веса делают их разными с самого начала (нарушение симметрии). Нули — ещё хуже: с ReLU вообще ничего не учится.
- **Почему веса маленькие, но не слишком.** С большими весами числа растут в несколько раз на каждом слое (в опыте: 2.6 → 13 → 69 → 412 → 2350 за 5 слоёв), и потом `np.exp` в Softmax выдаёт `inf`. Со слишком маленькими сигнал затухает (×0.01: в 20 раз на каждом слое). Для 1–2 скрытых слоёв `0.01` подходит; для глубоких сетей масштаб берут по числу входов: `np.sqrt(2 / n_inputs)` (инициализация Хе).
- Ошибка, которую нашёл: `np.random.rand` вместо `np.random.randn`.
  `rand` — числа от 0 до 1, все положительные. `randn` — дробные числа вокруг нуля (в основном от −3 до 3), примерно половина отрицательные.
  С `rand` все веса положительные, нейроны почти одинаковые, а во втором слое ReLU вообще ничего не обнуляла — слой стал линейным. Код при этом работал без ошибок.
- `np.random.seed(0)` — одни и те же «случайные» числа при каждом запуске, проще отлаживать.
- Проверка `Layer_Dense` на известных числах (`test_dense.py`, вспомогательный тест написал Claude): размеры совпадают даже у сломанного слоя, поэтому проверять надо сами числа. Ошибку в `forward` потом трудно отличить от ошибки в обучении — снаружи у них один симптом: loss не падает.

### 18.10 — Softmax

- Последний слой выдаёт произвольные числа, а нужны вероятности: каждая от 0 до 1, в сумме 1. Просто поделить на сумму нельзя — числа бывают отрицательными.
- Шаг 1: экспонента. `eˣ` всегда положительна, сохраняет порядок и усиливает разницу. Квадрат не подходит: `(−3)² = 3²`, «точно нет» стало бы «точно да».
- Шаг 2: делим на сумму строки. `[2.0, 1.0, 0.1]` → `[0.659, 0.242, 0.099]`.
- Переполнение: `np.exp(1000) = inf`, ответ превращается в `nan`. Поэтому сначала вычитаю максимум строки — ответ не меняется, потому что `e^(a−m) = eᵃ / eᵐ`, и `eᵐ` сокращается.
- Считается для каждого кадра отдельно — по строкам, `axis=1`, и обязательно `keepdims=True`. Без `keepdims` из матрицы `(3, 3)` вычитается не тот максимум, и сеть молча меняет ответ.
- Ошибка, которую нашёл: в знаменателе `np.sum` без `axis` — делилось на сумму всей пачки. На одной строке это не видно, поэтому проверять надо минимум на двух.
- Softmax ставится только в последний слой, в скрытых — ReLU.

### 19.10 — один объект на каждое место в сети

- У каждого слоя свой объект активации (`activation1`, `activation2`), даже если это одна и та же ReLU: объект запоминает, что через него прошло, и это нужно для `backward`.

## Неделя 2

### 22.10 — функция потерь и accuracy (`nn/losses.py`)

- Loss — одно число, насколько сеть ошиблась. Обучение — подбор весов, при котором loss уменьшается.
- Метки `y` — номера правильных жестов, например `[0, 1, 1]`.
- Cross-entropy: loss кадра = `−log(вероятность правильного жеста)`. Уверенно прав → около 0, сомневается → средний, уверенно ошибся → очень большой.
- Почему логарифм. Хорошая сеть угадывает все кадры сразу, а это произведение вероятностей. Произведение сотен чисел меньше 1 компьютер округляет до 0 (`(1/6)**500 = 0.0`). Логарифм превращает произведение в сумму, минус делает её положительной, деление на число кадров даёт среднее. Это метод максимального правдоподобия. Плюс логарифм сильно штрафует уверенные ошибки, а `1 − p` — нет.
- Как достать вероятности правильных жестов: `p[range(n), y]` — NumPy берёт номера строк и столбцов парами.
- `np.clip(p, 1e-7, 1 − 1e-7)` — чтобы не было `log(0) = inf`.
- В классе два метода: `forward` — loss каждого кадра, `calculate` — среднее.
- Ошибка, которую делал два раза: вызывал метод без объекта (`calculate(...)` вместо `loss_function.calculate(...)`).
- Accuracy — доля угаданных кадров: `np.mean(np.argmax(out2, axis=1) == y)`. `True` считается за 1, `False` за 0. Accuracy понятна человеку, а сеть учится по loss — он учитывает ещё и уверенность.
- `.ndim` — сколько у массива измерений (число 0, вектор 1, матрица 2). `axis` — номер одной оси внутри массива, считается с нуля: у матрицы только `axis=0` (строки) и `axis=1` (столбцы).

**Результат необученной сети** (6 жестов, 500 случайных кадров): loss = 1.792, accuracy = 0.166. Это ровно случайное угадывание: `−log(1/6) = 1.792`, `1/6 = 0.167`. Все вероятности около 0.167, потому что маленькие веса дают выходы около нуля, а `e⁰ = 1` у всех жестов.

**Готово:** прямой проход целиком — Dense → ReLU → Dense → Softmax → loss.

### 23.10 — обучение случайным поиском (`train_random.py`)

- Обучение — менять веса так, чтобы loss уменьшался. Первый, самый простой способ: прибавить ко всем весам маленький случайный шум. Стало лучше — оставить, хуже — вернуть лучшие веса.
- Шум прибавляется к **весам** (`dense1.weights` и т. д.), а не к выходам. Снаружи `dense1.weights` — это то же, что `self.weights` внутри класса. `layers.py` не меняется: `__init__` задаёт стартовые веса один раз, а обучение потом крутит их у конкретного объекта.
- Сравнивать с **лучшим** loss, а не с предыдущим: после отката «предыдущий» может быть плохим.
- `.copy()`: `b = a` не копирует массив, а даёт ему второе имя, и `+=` меняет оба. Копирую и при сохранении, и при возврате.
- Мои ошибки:
  - создавал данные и слои **внутри** цикла — каждый повтор начинался с новой случайной сети, и возврат лучших весов ничего не давал (10 000 лотерейных билетов вместо улучшения). Правило: всё, что живёт всё обучение, создаётся до цикла;
  - `import spiral as spiral_data` импортирует файл, а не функцию — нужно `from spiral import spiral_data`;
  - `elif loss > best` вместо `else` — при равенстве шум оставался в весах.
- Результат: старт ≈ 1.099 = −log(1/3) (3 класса), после 10 000 попыток loss 1.079, accuracy ≈ 0.38, улучшений 71 из 10 000. У Claude в похожем запуске 1.044 и 0.41 — случайный поиск сильно зависит от удачи. 100 000 попыток почти ничего не добавляют.
- Почему плохо: шум двигает все 21 вес сразу в случайные стороны. Половина изменений портит результат, и метод не знает, куда двигать каждый вес.
- Гиперпараметры — числа, которые задаю я, а не подбирает сеть: число повторов (10 000), размер шума (0.05), число скрытых нейронов (3). Сколько повторов нужно, видно по loss: перестал падать — дальше бесполезно.

### 24.10 — наклон одного веса (`numeric_grad.py`)

- Как узнать, куда двигать один вес: сдвинуть только его на 0.0001 и посмотреть, как изменился loss.
  **Наклон = (loss после − loss до) / 0.0001.** Знак — направление (минус: увеличивать вес, плюс: уменьшать), величина — сила влияния. Это **производная** loss по весу.
- **Градиент** — наклоны всех весов. **Градиентный спуск**: все веса меняются сразу, каждый против своего наклона: `вес = вес − скорость_обучения × наклон`. Скорость обучения (learning rate) — гиперпараметр, размер шага.
- Мои ошибки: оставил цикл и шум от случайного поиска — получались огромные «наклоны», потому что изменение loss от шума 0.05 на всех весах делилось на 0.0001; менял вес в копии, а не в сети; вычитал 0.0001 на каждом повторе, и знак переворачивался. Цикл здесь не нужен: всё делается один раз.
- Результат: наклон `dense2.weights[0, 0]` = 5.44e-05 = 0.0000544 (`e-05` — умножить на 10⁻⁵).
- Почему такой маленький: вероятности около 0.333, а выход скрытого нейрона, который входит в этот вес, почти ноль (в среднем 0.003), потому что веса маленькие. Сдвиг веса почти ничего не меняет.
- **Наклон веса ≈ (что входит в вес) × (насколько loss реагирует на выход нейрона).** Проверка: по этой формуле 0.00005441096, замер в лоб 0.00005441119. Вход у каждого веса я уже сохраняю в `self.inputs`.
- Почему замер «в лоб» не годится для обучения: на каждый вес нужен ещё один прямой проход. У сети жестов 3142 веса → 0.63 с на один шаг, 10 000 шагов ≈ 2 часа. **Backprop** считает наклоны всех весов за один проход назад по сети (цепное правило), примерно за время пары прямых проходов. Медленный способ останется для **проверки градиентов**: сравнить его с backprop.
- Даже с правильными наклонами сеть из 3 нейронов застряла около loss 1.08 — ей не хватает изломов для спирали. Нужно больше нейронов.

**Готово:** прямой проход, loss, accuracy, случайный поиск, производная «в лоб».
**Дальше:** производные и цепное правило → `backward` в слоях.
